# 九九乘法牌 · 数字小侦探

按课堂玩法制作的家庭猜牌游戏，支持与电脑对战，以及两人共用一台设备轮流玩。

[GitHub Pages在线游戏](https://houde0820.github.io/99-card-detective/)

## 运行

没有第三方依赖，也不需要构建。直接用浏览器打开 `dist/index.html` 即可玩。

也可以在项目根目录启动本地服务：

```sh
python3 -m http.server 8766 --bind 127.0.0.1 --directory dist
```

然后打开 <http://127.0.0.1:8766/>。

## 当前规则

- 所有牌共用一个牌堆，开局每人可选4、5或6张，默认5张；范围可选初级1–39、中级1–49或0–39。
- 同一数字范围的牌放在一列，每列从下到上递增，各列从右向左由小到大。默认有牌的列靠右排列，空列不占位置；需要结合牌面推理每列的真实范围。
- 例如只有0–9和20–29有牌，两列相邻靠右；补进10–19的牌后插入中间，20–29移到右数第三列。
- 设置中的「列的摆放」可切回固定位置保留空列。初级有四个范围，中级增加40–49范围。
- 口诀内数字的牌背随机显示一个因数，两个乘数都在1–9内；口诀外数字显示X。
- 点击对方未翻开的牌，在牌上输入数字，点✓确认、点×取消。
- 猜对翻开留桌；猜错，对方从公共牌堆抽两张，按大小插入。不足两张时抽完剩余牌。
- 双方轮流行动，先猜完对方桌上全部牌的一方获胜。
- 猜错的牌保留橙色标记和最近的错误猜测，重新排序和刷新后仍保留。
- 提示与电脑根据可见分组和顺序、牌背提示、已知数字和错误猜测推理，不读取暗牌答案、隐藏的列范围或牌堆内容。翻开的牌可以确定所在列的范围。

双人模式换人时遮挡牌面。对局保存在当前浏览器的本地存储中，支持继续旧对局。

## 页面布局

游戏名称、当前操作提示、轮次和设置合并在顶部一行。主页集中展示双方牌桌和公共牌堆；猜牌反馈显示在牌桌标题旁。各列不显示数字范围标签；默认只显示有牌的列并靠右排列，通过分组顺序与牌面推理。刷新后已有对局保留原牌和猜错记录，并使用右对齐布局；显式选择固定位置的对局继续采用固定位置。右上角「设置」集中放置皮肤选择、新对局选项，以及可展开的玩法与推理说明、对局记录。

## 视觉主题

积木主题使用四色数字分区、几何形状和带厚度的卡片与按钮。设置中可切换晴空、薄荷、莓果三套配色，刷新后保留选择，换肤不影响对局或正在输入的数字。没有卡通插画，也没有外部图片或字体依赖。

还可以切换到「植物大战僵尸」主题：经典草坪分行、木质种子卡槽、阳光徽章、厚描边与种子包牌面；因数线索和自己的数字采用深浅不同的绿色窗口，猜中和猜错状态保留文字标记。原来的三套配色继续保留，切换后自动记住选择。

后续换皮肤主要修改语义样式变量；组件布局和游戏规则独立。入口与添加主题的方法见 [THEMES.md](THEMES.md)。

## 随机权重

新对局中，30–39号牌的抽取权重乘以0.85；X牌的抽取权重也乘以0.85，两项叠加。其他牌权重为1。有其他合法因数可选时，因数2的提示权重为其他因数的0.85倍。

开局给两人发的前8–12张牌（每人所选张数的两倍）额外微调：5–9号牌的抽取权重再乘以0.85，X牌的抽取权重也再乘以0.85。两个玩家都按所选的4–6张应用同样的规则；这两项额外权重只作用于开局，后续补牌沿用原有权重。

每个数字仍各有一张牌，这个调整影响抽牌顺序，使30–39和X牌在前期略少出现。只能提示2的牌仍提示2。已开始的对局继续使用其既有牌堆、桌上牌和提示；刷新网页后新开一局应用新权重和所选的开局张数。

## 修改与验证

`dist/index.html` 是主源码与交付文件，包含样式、独立游戏引擎和页面交互。保持单文件是为了方便离线使用。

安装Node.js后，在项目根目录运行：

```sh
node check-game.cjs
```

测试覆盖1800局确定性对局，包括三种牌范围和4–6张的全部组合，以及公共牌堆守恒、可配置开局、排序插入、位置与X推理、牌堆耗尽、旧存档迁移和电脑的暗牌独立性。另有两项各5000组固定种子的权重对照，分别检查30–39与因数2、X牌的频率只作轻微下降。另外5000组固定种子的开局对照检查两名玩家的5–9和X比例轻微下降、完整牌组与因数不变，以及旧存档不重新发牌。另有60个小牌桌的穷举对照，验证压缩列的跨范围推理、翻牌定位和隐藏范围独立性，并检查补牌插入后猜错标记不丢失。页面交互改动还需要在浏览器中检查。

## 发布与代码同步

GitHub Pages工作流位于 `.github/workflows/pages.yml`。

- 每次推送到 `main`，自动执行规则测试和随机权重测试，全部通过后直接发布该提交的 `dist/`。
- Pull request只运行测试，合并到 `main` 后自动发布。
- 发布使用同一份 `dist/index.html`，无需复制源码到另一个发布目录。
- 可以在仓库Actions页面手动运行 `Test and deploy GitHub Pages`。
- 发布产物中的 `version.json` 记录本次发布的提交SHA，可用于确认网页与源码是否一致。

### 首次启用

1. 打开仓库 **Settings → Pages**。
2. 在 **Build and deployment → Source** 中选择 **GitHub Actions**。
3. 在 **Actions → Test and deploy GitHub Pages** 手动运行一次；后续 `main` 更新会自动触发。
